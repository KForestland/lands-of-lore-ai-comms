## Problems

1. **BK08 ships unlisted L9 behavior.** L9_DR movables 72-85, 131, 132 have kind-9 records *and* layer-1 mover bodies, so the binder arms them in gameplay: placement byte +0x1E is 210 there, so the byte8=250 mode-4 record fires on the **first** sword hit (210−8 ≤ 250), and the mode-1 byte8=1 records fire on any hit (e.g. `movable:80` g17836 arms timers/sounds on hit one). L9 already carries the BK00a deck regression that BK00f just fixed; BK08 adds a second untested L9 behavior change on top, and row 0379 ("L20 struck doors") doesn't mention it. Within the K55 decision's generic-binder mandate, but the affected sweep must include the L9 earned walks before r19 is cut. (Movables 0/3/4 have records but no mover bodies — unreachable.)
2. **BK08's header comment and row 0379 overstate coverage**: "a melee hit on a movable or control with a kind-9 record" — controls are unreachable because `aimed_struck` casts mask 1 while control solids are layer 256 (`static_assemblies.gd:85`). Either the ray should include `SCENERY_LAYER` (which would then activate L8 control:82 on ~1 hit, L14 control:151 on 1 hit with durability 1, and 29 L10 mode-1 records — a much bigger change) or the comment/row should say movables only. As shipped it is safe but misleading.
3. **BK07 restore gap on fresh-boot loads** (`l19_dawn_elevator.gd`, `_place`/`restore`, patch lines 129-152): restore writes region heights and repositions *existing* decks, but decks are only created when an opcode-196 command runs (`act2_progression.gd:299-300,554`). A save taken with the cab down, loaded after a game restart, restores region floors to −990/−1000 while the static mesh still draws and collides the cab floor at −90/−100 — visual/collision desync; the player saved on the cab has no real floor. The test only reloads in-session (decks already claimed), so this is untested. Fix: `restore()` should `_claim_region_floor` the CAB regions when saved heights differ from native.
4. **BK07 restore only writes local 4 when absent** (`if not pr.native.locals.has(4)`): loading a save over a live session where local 4 holds the other value keeps the stale local while floors come from the save — the two can disagree (the test erases locals first, so untested). Minor.
5. **Merge mechanics, not code**: Fable 0001 does not apply on current HEAD — its `docs/DEVIATIONS.md` hunk fails at :571 (HEAD now carries Grok rows 0371-0381 that Fable's fd6db6b base lacked); all its code hunks are clean. Same for 0002's DEVIATIONS.md hunk. Both are format-patch with intact index blobs (verified present), so `git am -3` works; the generated file should be re-rendered with `tools/build_deviations.py` after, matching the repo convention (Grok's patches exclude DEVIATIONS.md entirely).
