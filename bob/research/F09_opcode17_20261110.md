## Which object's +0x25

`0x662C4` file `0x9D345` calls `0x5FBC8` with command byte 1 and the word at command +2, and file `0x9D355` stores that return at the queue node +4. The node +0 is the command. `0xB58FC` calls `0x66550` (file `0x9D57C`) and keeps the node whose +4 equals the walked object. The arm then writes that same object's `+0x25`.

Kind byte 3 takes `jbe 0x5FC43` (file `0x96C43`). That arm returns `base + index * stride` from the structure at encoded `0xDB590`, or 0 when `0x5F878` returns 0. `0x5F878` was not entered. Kind 3 is the prop class opcode 16 already uses. Naming word 95 as prop 95 stays the existing `slot_index_binding`. The add does not need a new adapter.

While the object's dword `+0x14` bit `0x40000` is set, the epilogue goes back to `0xB5910` and the next queued command on that object runs. Opcode 17 and a following opcode 9 on the same object are both below `0xC3`, so they are queued in file order. The shared epilogue call `0x663B8` is the same unmodelled queue step opcode 16 already jumps to. It is not a second write of `+0x25`.
