# Grok review — 2026-11-01

I agree with the owner rule. A checkpoint that ends complete false is not a reason to keep reading bytes. When the hintbook, a longplay, the owner, or a finished oracle run already says what the player sees, the builder should implement that behaviour and name the source. I also agree with W11–W13, W16, W19, and with the changes adopted from Astra: preflight, narrow lint, separate shard directories, semantic commands plus a smaller rendered suite, real continuation plus leases, oracle only for an unknown, and a dashboard that separates audited, implemented, headless, and rendered.

W18 is the right order for a who-writes question, and it needs three limits that this lane already hit. Re-measure the live EIP map on that process before naming an address. The recipe text that subtracts 0x10020000 does not match the map measured on the running oracle. One DOSBox only, quit only through its cmd file, and run reset_copy.sh only after that process is gone. A kill leaves the cache dialog, and the menu driver does not clear it. Arm one watch for one save and one moment. A logged store that leaves the watched byte unchanged is not the writer.

W19 should stay, with the effect line written as the player-visible result when that result is known. Hintbook facts stay graded HINTBOOK with the page. A store that was seen is PROVEN. A byte that did not change stays in the sentence as unchanged. Builders should not have to turn an instruction address into a quest step.

I would not drop W17's lease. status/grok.md should name the live session and the one open question so a second worker does not launch a second DOSBox. I would not make the oracle a gate for a book step Astra can already host.

Risks this plan underweights: the oracle address map changes between launches, so a copied linear address from an older note labels the wrong instruction. The cache dialog after an unclean quit stalls the next run on a modal the keyboard path does not answer. Re-issuing hintbook items that already have checkpoints creates duplicate board lines and no new behaviour. Display :3 is the oracle display. A rendered Godot run on that display collides with the session even when the reservation text still says HELD.

Three additions from this lane:

1. Oracle preflight, in the same spirit as W11: one dosbox, display free, cache files pristine or the dialog will be answered No, the named save parked, affinity on CPUs 16-23. Fail in seconds, before the menu.
2. A behaviour card next to the contract: source (page or session), what the player does, what changes, what stays unknown. The builder implements the card. Instruction addresses stay the witness.
3. A lease line in status/grok.md with the live pid and the single open question. The next worker reads it and does not start another session.
