An object-2 dword becomes an analysis address by adding `0x59024`. Object-5 fixups are keyed the same way as the Cave loader: page `1 + (analysis - 0x59024) / 4096`, source `(analysis - 0x59024) % 4096`, kind 7, flags 0 or 16. No host was added. No test was run. ## The walk

Prologue pushes EBX, ESI, EDI, EBP and subtracts 8. The only argument is `[esp+0x1C]`.

`[esp+0x1C]` is the struct. `[struct]` is the record-pointer array. `[struct+8]` is the count; a count `<= 0` returns. `[struct+0xC]` is a parallel array of pointers. Each iteration stores that parallel pointer at `[0xB7D80]` before it reads the record. The fixup at `0xB8BD4` is object 5, offset `0xB7D80`.

For each record pointer in EBX:

- `test byte [ebx+5], 1` / `jne` next. Bit 0 set skips the record.
- `test byte [ebx+4], 0x90`. Nonzero: ESI = dword `[0x22C5A]` (`8B 35` at `0xB8BE5`, fixup at `0xB8BE7`, object 5 offset `0x22C5A`). Zero: AX = word `[0x22C58]` (`66 A1` at `0xB8C0D`, fixup at `0xB8C0F`, object 5 offset `0x22C58`), then `movsx esi, ax`.
- EAX = zero-extended word `[ebx+8]`. If EAX is above ESI, `sub word [ebx+8], ax` and the record does not fire. AX is the low 16 bits of the saved clock. On this path the clock is at most the countdown word, so AX equals the clock.
- Otherwise the countdown has been reached. `call 0xB8AC4`, keep the low 16 bits, and write word +8 before the fire test. If that low 16 is above the clock, the new word is the old word plus `(reload - clock)`. Otherwise the new word is 0. A later reject does not undo the write.
- The fire test reads the record that starts `byte [ebx]` bytes after this record, which is the following length-prefixed record. If byte 0 or byte 1 of this record is 0, that pointer is 0 and EAX is forced to 1. If the following record's byte +1 is `0x13`, the walk zero-extends its word +2, calls `0x66AB0`, and a zero return skips the call. Any other following kind forces EAX to 1.
- A nonzero result zero-extends word `[record+2]`, calls `0xB8D04` (`A1 14 B5 02 00` / `ret`, fixup at `0xB8D05` object 5 offset `0x2B514`), adds that dword, and calls `0x646EC` with the sum. The region walker adds `[0x2B51C]` instead. These are different globals.

`0xB30AC` (entry `0xB30AC`) calls `0xAB0F8`, then pushes `0xB7DA4` and calls `0xB8BA0`. The region walker `0xD26B0` is a later call in the same function, at `0xB31F9`. The calls between them were not entered. Direct callers of `0xB30AC` remain the six named in the region-event note.

## Reload

`0xB8AC4` takes the record and does not write word +8. The caller writes the low 16 bits of the return.

- Byte +4 bit `0x20` set: the value is byte +6. `0x12415C` is not called.
- Bit `0x20` clear: push byte +7, push byte +6, push `0x221D8` (fixup at `0xB8AE4`, object 5 offset `0x221D8`), call `0x12415C`.
- Then bit `0x10`: `imul ax, word [0x223A8]` (fixup of the word at `0xB8AFE`).
- Else bit `0x80`: discard the call result and return `(byte +6) * word [0x223A8] * 0x3C`. The low 16 bits are what the caller keeps, so this product can truncate.
- Else: return the value shifted left 8.

`0x12415C` reads three arguments. The first is the address pushed above, so the seed is the dword at `0x221D8`. The second is byte +6 and the third is byte +7. Equal bytes return that byte and do not write the seed. Unequal bytes swap so the second argument is the lesser, subtract to form the span, and update the seed with `imul` by `0x41C64E6D` and `add` of `0x3039`. The returned value is that draw plus the lesser byte, and the compare that retries keeps it inside the inclusive span. `0xA01BB` stores the return of `0x14FA79` into `[0x221D8]`. That callee was not entered, so the initial seed is UNKNOWN.

## Scale word

`[0x223A8]` is not an image byte. A scan of absolute `disp32` and `moffs` forms from file `0x56000` to the end of the image, accepting only a hit whose object-5 fixup names `0x223A8`, found one store: `mov ebx, 0x3C` at `0x14E7E4`, `call 0x16148C`, then `mov dword [0x223A8], ebx` at `0x14E7F1`. `0x16148C` is `push ebp; mov ebp, esp; push ebx` and `pop ebx; pop ebp; ret`, so EBX is still `0x3C` (60). No other absolute store or LEA of that address was found. The function that contains `0x14E7F1` was not given its own entry search, and a non-absolute writer was not ruled out. After this store, the word the reload multiplies by is 60.

The stored countdown words match that formula evaluated at 60. This is a check of the 616 records, not a second read of the global. All 176 records with byte +4 = `0x30` store `byte +6 * 60` (prop 93 is 5 and 300). All 95 with byte +4 = `0x80` store `byte +6 * 3600` (67 of them are byte +6 = 15 and word 54000). All 43 with byte +4 = `0x20` store `byte +6 << 8`. All 285 with byte +4 = `0x10` store a multiple of 60 whose quotient sits in the inclusive range of byte +6 and byte +7. All 17 with byte +4 = `0x00` store a multiple of 256 whose high byte sits in that same range. The random arms' placement words are one value the reload can return. They are not a roll performed at load.

## Who puts a record on the list

The struct the caller pushes is the memory at `0xB7DA4`.

| offset | absolute | use |
| --- | --- | --- |
| +0 | `0xB7DA4` | pointer to the record-pointer array |
| +4 | `0xB7DA8` | slot count, shifted left 2, passed as a size |
| +8 | `0xB7DAC` | live count. The walk reads this |
| +0xC | `0xB7DB0` | pointer to the parallel pointer array |
| +0x10 | `0xB7DB4` | slot count of that array |
| +0x14 | `0xB7DB8` | live count of that array. The walk does not read it |

`0xAEBFA` writes 0 to the live counts and fills both arrays through `0x14F8A4`. No direct `E8` in the scanned range targets `0xAEBFA`.

`0xAEC74` is the load scan. Its only direct caller is `0x9C998`, which pushes `[ebp+0x28]`. A zero argument clears byte `[0xB7D8C]` and returns. A nonzero argument sets that byte to 2 and walks the list at `[0xB7D6C]`. An empty list still calls `0xB30AC`, so the expiry walk runs, then calls `0xE066C` with `0x227A4` and `0x22574`. On a node it calls vtable slot +`0xB8` and keeps records whose byte +1 is 2. A record is appended only when byte +5 bit `0x80` is clear and bit 0 is clear. If bit 1 is also set, the same region resolver used by opcode 14 arm 3 must see bit 2 of word `[region+0x28]` set; otherwise the record is left off the list. An accepted record gets byte +5 bit `0x80` set, is stored at the next slot of the record array, and the node pointer is stored at the next slot of the parallel array. Both live counts increment. Bit `0x80` of byte +5 is the "already appended" bit. The expiry walk does not test it. Bit `0x80` of byte +4 is a different byte and selects the `* 0x3C` reload.

Opcode 14's switch is `0xB47B4`. Command byte 6 counts kind-2 records, and `mov esi, ebx` at `0xB4815` makes ESI and EBX the selected record before the jump. Command byte 4 above 6 returns 1 at `0xB478E` and does not write. EBP is the command.

Arm 3 at `0xB485C` returns immediately when byte +5 bit 0 is already clear. Otherwise it clears that bit. If command byte 5 is nonzero it calls `0xB8AC4` and stores the low 16 bits at word +8. If byte +5 bit 1 is clear, it appends. If bit 1 is set, it appends only when the region word's bit 2 is set; a failed test returns 1 and leaves bit 0 already cleared. The append sets byte +5 bit `0x80`, increments `[0xB7DAC]`, stores the record, increments `[0xB7DB8]`, and stores `[esp+0x14]`, which is the object argument.

Arm 4 at `0xB494B` returns immediately when byte +5 bit 0 is already set. When bit `0x80` is set it clears that bit and calls `0xDDF54` twice: `0xDDF54(0xB7DA4, record)` and `0xDDF54(0xB7DB0, object)`. `0xDDF54` finds the pointer, decrements the struct's +8 count, and slides the tail down. A missing pointer leaves the count alone. Arm 4 then sets byte +5 bit 0. A nonzero command byte 5 also rewrites word +8 from `0xB8AC4`.

Arms 0, 1, and 2 store command byte 5 at record byte +4, +6, and +7. Arm 5 at `0xB49BA` always writes `0xB8AC4`'s low 16 bits to word +8 and does not read command byte 5. Arm 6 at `0xB49D1` calls `0xB8B24`. That body was not entered.

## Clocks

No absolute store and no absolute LEA of `[0x22C58]` or `[0x22C5A]` survived the same fixup filter. The word has 13 loads. The dword has 28, including the walker's own `mov esi` at `0xB8BE5`. Several of those loads are followed by `sub` of some other word. Those instructions do not write the clock. The two addresses do not overlap: the word occupies `0x22C58`–`0x22C59` and the dword occupies `0x22C5A`–`0x22C5D`. A writer that used a base register plus a displacement would not have been in this scan. The writer stays UNKNOWN, and so does the unit of the subtracted value.
